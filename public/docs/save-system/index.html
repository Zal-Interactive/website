com.zalinteractive.save-system

Save System

Save System is a key-value store for game state. It is built for open worlds: state is grouped into partitions that are loaded and saved independently, so a game reads only the parts of the world it needs.

  • Keys. A SaveKey names one value. It always contains the partition the value belongs to and a ‘/’-separated path inside that partition.
  • Partitions. A partition is a group of keys that is loaded and written together. Add a Save Partition component to a GameObject to make it and all of its children one partition. The nearest Save Partition above an object wins. Objects with no Save Partition above them use the built-in global partition.
  • Identities. A Persistent Identity component gives a GameObject a stable key inside its partition. An identity under another identity in the same partition nests its key under the parent’s key.
  • Slots. A DataStore is opened for one save slot. Slots are stored separately, so each one is its own world.
  • Storage. The store keeps its data in an ISaveStorage. FileSaveStorage stores each partition as a JSON file. InMemorySaveStorage keeps it in memory.

Every change is written to storage immediately. A partition is loaded the first time one of its keys is used and stays in memory until you unload it.

In online co-op, only the host opens and changes the store. Clients receive world state through your networking code.

The package requires Unity 6.0 or newer.

Set up partitions

  1. Add Save Partition to the root GameObject of each area that loads and unloads together, for example the root of an additive scene or a dungeon.
  2. Enter an Id, such as cave_03. Use letters, digits, ’_’ and ‘-’ only, keep it unique across the world, and do not change it after release. When left empty, a GUID is assigned.
  3. Add Persistent Identity to each GameObject whose state you save. Its id is assigned automatically.

A Save Partition on a prefab asset keeps its Id empty, so instances do not share one partition. Give each placed instance its own Id.

Partition names become file names. On Windows and macOS, file names ignore case, so do not use two partition names that differ only in case.

Open a store

Create the storage and open the slot once, on the host. Open returns a Result; check it before use.

var opened = DataStore.Open(new FileSaveStorage(), "slot1");
if (opened.IsFailure)
{
    Debug.LogError(opened.Error);
    return;
}

var store = opened.Value;

FileSaveStorage writes to Saves/<slot>/<partition>.json under Application.persistentDataPath. Pass a folder to the constructor to store saves elsewhere.

Read and write values

Build keys from an identity, a partition, or the global partition with Child.

var key = GetComponent<PersistentIdentity>().Key.Child("open");

store.Set(key, true);
var open = store.Get(key, fallback: false);
if (open.IsSuccess)
{
    door.SetOpen(open.Value);
}

store.Set(SaveKey.Global.Child("time-of-day"), 13.5f);

Get returns the fallback when nothing is stored. Has reports whether a key is stored. Remove deletes a key. Values are converted to JSON with Newtonsoft Json.NET, including Vector2, Vector3, Quaternion, and Color.

Set and Remove write the partition to storage before they return. When the write fails, the previous value stays in memory and the call returns SaveError.StorageFailed.

Unload partitions

A partition loads automatically the first time one of its keys is used. Call Unload when its area leaves the world to free its memory. Nothing is lost, because every change was already written.

store.Unload("cave_03");

IsLoaded reports whether a partition is in memory.

Handle failures

Store operations never throw. They return a Result with a SaveError:

  • InvalidSlot, MissingStorage: Open received a bad slot name or no storage.
  • InvalidKey: the key has an invalid partition name or an empty path segment. Check SaveKey.IsValid.
  • StorageFailed: the storage could not read or write.
  • CorruptPartition: the stored partition is not valid JSON. It is not loaded and cannot be overwritten, so its data stays available for recovery.
  • ValueNotConvertible: the value cannot be converted to or from the requested type.

The package logs the details of each failure to the Console.

Store saves elsewhere

Implement ISaveStorage to keep saves somewhere other than files, for example in a console’s save API or a cloud service. It reads, writes, and deletes one text per partition of a slot. A failed write must leave the previous text readable, and implementations return a StorageError instead of throwing.

Consoles require their platform save APIs, so FileSaveStorage does not cover them. Some console platforms also limit how often a game may write; buffer writes in your ISaveStorage implementation when needed.
