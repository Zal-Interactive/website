Unity Annotator

com.zalinteractive.unity-annotator

What you can do

Unity Annotator turns visual feedback in the Unity Editor into screenshots with numbered markers, notes, and captured target information. Collect several screenshots in one batch, then give an agent a request it can retrieve through Unity’s command tool.

  • Capture a window or the entire Editor. Freeze a Scene view, Game view, or another visible Editor pane. An entire-editor capture includes the main window’s toolbar and docked panes.
  • Mark a point or an area. Place a marker at an exact location or draw a rectangle around a region, then write what you want to change. A dashed border identifies the image that accepts annotations; the rest of the Editor remains usable.
  • Identify an object or control. Fresh captures can attach GameObject references or Editor-control descriptors to your notes. Choose from the clicked target and its ancestors when several candidates overlap.
  • Switch tools beside the image. The compact toolbox follows the captured window and shares its selected mode with Unity Annotator. Saved images and entire-editor captures support Point and Area.
  • Revise and reopen your feedback. Move markers, resize areas, edit notes, and undo active screenshot edits. Drafts survive Editor restarts, and saved screenshots can be reopened without their original window.
  • Hand off a complete batch. Add a shared message, send the batch, and copy its request into your agent’s chat. The agent can retrieve notes, target descriptors, original images, and numbered previews. A receipt shows when it has read the batch.

Start by opening Window > Unity Annotator. The following pages take you through capture, annotation, editing, and handoff. Unity Annotator is an Editor tool; your agent needs file access to the computer running Unity.

Capture and collect

Open Window > Unity Annotator in Unity 6.0. The package uses Common, Unity Pipeline, Newtonsoft JSON, and uGUI.

Click Add screenshot… to choose a visible Editor window. The next page shows the capture choices. Each finished screenshot becomes a card in the tray, where its Note fields remain editable.

Figure 1

Use the annotation tools to place markers and write a note for each one. Finish the screenshot before adding another; several screenshots can share a batch. Marker numbers are unique across that batch.

During Play Mode, capture pauses playback. Finishing or cancelling restores the previous pause state.

Choose what to capture

After Add screenshot… (Figure 1), click Annotate in the center of the pane you want to capture. Cyan corner brackets mark its content bounds. Only active tabs in shown windows receive a button. Switching tabs, resizing panes, or opening a floating window updates the choices. Other controls remain usable while you choose.

Figure 2

Alternatively, click Capture entire editor to capture the main Unity window, including its toolbar and docked panes. Use Cancel or Escape to leave the choices without taking a screenshot.

Figure 3

An entire-editor image opens in a separate preview for Point and Area annotations. Capture a pane individually for object or Editor-control picking.

This is an on-screen image: overlapping windows can appear within the main window’s bounds. Separately positioned floating windows are not stitched into the image. A disabled capture button explains why screen capture is unavailable.

Stay in annotation mode

After capture, a cyan dashed border marks the frozen image that is ready to annotate. Click inside it to add a point, or drag to mark an area. The image intercepts input to the underlying window; other panes and controls outside the border remain usable.

Figure 4

Keyboard input inside the image is reserved for annotation commands and notes. The border and toolbox stay out of original and exported images.

Use the toolbox

Click Point to place a marker or Area to draw a rectangle. These are the first two toolbox icons, from left to right. Hover an icon for instructions.

Figure 5

The third icon, Game object, picks a Unity object; the fourth, Editor control, picks a control and its ancestors. The Picking pages explain how to choose the exact target.

Figure 6

The toolbox follows the target. It moves above the window when there is no room below, or inside its bottom edge when neither position fits. Saved screenshots and entire-editor captures offer Point and Area; the disabled picking icons explain why.

Use the Annotator controls

You can also switch between Point and Area in Unity Annotator. Both sets of mode buttons share the same selection.

Figure 7

Game object and Editor control use the same picking modes as the toolbox.

Figure 8

Click Finish screenshot, or press Escape from the image, toolbox, or Unity Annotator, to keep your annotations. Cancel discards a fresh screenshot; during saved-image editing it restores the annotations present when you opened it.

Adjust your annotations

While capturing or editing a screenshot, drag a point to move it. Drag inside an area to move it; drag its lower-right corner to resize it. Edit Note beside its marker or in the tray; both fields change the same note.

Figure 10

Boxes stay inside the capture. Saved PNG previews contain numbered markers only.

Select and remove markers

Click a marker number in the tray to select it. If note boxes cannot all fit inside the capture, the tray reports overflow; selecting a marker there shows its note. Delete removes the marker.

Figure 11

Typing within one note is one undo step; the session retains its latest 100 edits. Selection clicks and undersized areas do not consume history. Deleted numbers are never reused.

Review a finished screenshot

Click a thumbnail or View screenshot to review the numbered preview after finishing. Notes and marker deletion remain available in the tray (Figure 11).

Figure 12

Use Edit screenshot to place or adjust markers again. Remove screenshot deletes a draft screenshot.

Figure 13

Reopen a saved screenshot

Click Edit screenshot on a draft card (Figure 13). Its original image opens with editable markers and notes, even after a restart or closing its source window. Finish before editing another screenshot.

Figure 14

Add Point/Area markers or adjust annotations (Figures 7 and 10). Live picking requires a fresh window capture; existing targets remain. Resizing preserves marker positions and image proportions. Saved editing leaves playback running.

Edits autosave. Finish screenshot, Escape, closing either window, recompilation and Play transitions retain them. Cancel restores opening annotations while keeping other screenshot edits. Reopening resets Undo history; cancelled numbers stay unused. Submitted batches remain read-only.

Undo and retain your edits

Press Ctrl/Cmd+Z, or click Undo, to reverse active screenshot edits from either window. Finished-screenshot notes and the batch message keep their own text behavior.

Figure 15

For a fresh capture, closing or resizing its source window, changing Play Mode, or recompiling ends annotation mode and retains its annotations. Saved-screenshot resizing preserves the annotation geometry instead.

An unavailable or invalid original prevents reopening; the draft and files are preserved. Storage errors retain edits in memory: restore access and edit a note to retry saving before closing Unity.

Geometry is expressed as 0–100 percentages from the original image’s top-left. An area uses x, y, width, and height. Each capture retains its original PNG separately from its numbered preview.

Choose the exact target

Select Game object on a Scene or Game view capture and click a visible object. Select Editor control on another Editor window capture and click a control. Candidates and their ancestors appear below the annotation tools.

Figure 16

Click Select beside a candidate to annotate that target, or focus its button and press Return. A GameObject field pings on click and selects the object in Unity on double-click. It is read-only: you cannot replace the captured reference by dragging or using an object selector.

Figure 17

Understand captured targets

Scene and Game objects. Scene captures support terrain and overlapping collider-free meshes and sprites. In Game captures, uGUI graphics remain pickable when their raycast target or gameplay interaction is disabled.

Dense overlaps show a warning if a camera reaches the 64-object candidate limit; isolate the intended object and recapture to see deeper candidates.

Scene picking uses the captured Scene view’s camera and viewport; Game picking uses its game cameras, zoom and letterboxing. Moving the Scene camera or changing the captured camera or viewport invalidates picking; finish and recapture.

uGUI uses rendered triangle geometry and masks; transparent texture pixels and custom shader clipping can still produce broader candidates. Camera stacking and custom rendering may need a point or area plus a descriptive note.

Editor controls. UI Toolkit targets retain type, name, classes, hierarchy position, bounds, binding path, and available source assets. Availability reports changes to source assets or the capture’s Play context. Bound Inspector fields also identify the inspected objects.

IMGUI candidates use the window name followed by area. Their bounds and window/Inspector context describe the captured region, rather than an exact retained control.

Send a batch

Add a Message to agent if several markers need a shared instruction, such as “align #3 with #1.” Finish the active capture and complete every note, then click Send to agent. Missing notes or storage failures leave the draft available for correction and retry.

Figure 18

Drafts and submitted batches survive Editor restarts beneath UserSettings/UnityAnnotator. Submitted batches cannot be edited.

Give the request to your agent

Click Copy request and paste it into your agent’s chat. You can copy the current request at the bottom of the window or an earlier request from Sent batches. Sending does not wake an idle chat.

Figure 19

Through the existing Unity command tool, the agent can request:

{
  "project_path": "/absolute/path/to/project",
  "command": "get_annotation_batch",
  "args": { "batch_id": "<submitted-batch-id>" }
}

Retrieve and manage sent batches

The agent can use list_annotation_batches to get pending summaries in batches. get_annotation_batch returns versioned metadata, all notes and target descriptors, and absolute paths to each original and preview PNG. All three commands carry schemaVersion: 1.

After reading a batch, the agent calls acknowledge_annotation_batch with the same ID. Waiting for agent changes to Read by agent after retrieval; the receipt does not mean the requested changes are complete.

Open Sent batches to review earlier requests. Hover a dated heading to see the full batch ID. Reads and repeated acknowledgments keep the files; use Delete beside a batch to remove it explicitly.

Figure 20

Runtime targets expire with their original Play session, while their screenshots and captured identity remain available as evidence.
