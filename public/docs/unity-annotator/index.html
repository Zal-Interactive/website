Unity Annotator

com.zalinteractive.unity-annotator

Capture and collect

Open Window > Unity Annotator in Unity 6.0. The package uses Common, Unity Pipeline, Newtonsoft JSON, and uGUI. Your agent must be able to read files on the computer running Unity.

  1. Click Add screenshot…, then choose the Editor window to capture. Its visible content becomes a frozen image.
  2. Select Point and click, or select Area and drag a rectangle. Add a Note beside every marker or in the tray.
  3. Click Finish screenshot. Repeat for another window to collect more screenshots in the same batch.

Figure 1

During Play Mode, capture pauses playback. Finishing or cancelling restores the previous pause state. Each screenshot can contain several annotation types; marker numbers are unique across its batch.

Valid GameObject targets appear as read-only object fields. Click to ping the object; double-click to select it. You cannot replace the captured reference by dragging or using an object selector.

Adjust your annotations

While capturing or editing a screenshot, drag a point to move it. Drag inside an area to move it; drag its lower-right corner to resize it. Click a marker number in the tray to select the annotation. Object fields navigate to the Unity object.

Figure 2

Edit Note beside its marker or in the tray; both fields change the same note. Boxes stay inside the capture. If they cannot all fit, the tray reports overflow: select a marker there to show its note. Saved PNG previews contain numbered markers only.

Delete removes a marker. Undo or Ctrl/Cmd+Z reverses active screenshot edits from either window. Finished-screenshot notes and the batch message keep their own text behavior. Typing within one note is one undo step; the session retains its latest 100 edits. Selection clicks and undersized areas do not consume history. Deleted numbers are never reused.

For a fresh capture, Cancel discards the screenshot. Finish screenshot or Escape keeps it. Closing or resizing its source window, changing Play Mode, or recompiling ends the overlay and retains its annotations.

After finishing, click a thumbnail or View screenshot to review the numbered preview. Notes and marker deletion remain available in the tray; Remove screenshot deletes a draft screenshot. Use Edit screenshot to place or adjust markers again.

Geometry is expressed as 0–100 percentages from the original image’s top-left. An area uses x, y, width, and height. Each capture retains its original PNG separately from its numbered preview.

An unavailable or invalid original prevents reopening; the draft and files are preserved. Storage errors retain edits in memory: restore access and edit a note to retry saving before closing Unity.

Reopen a saved screenshot

Click Edit screenshot on a draft card (Figure 1). Its original image opens with editable markers and notes, even after a restart or closing its source window. Finish before editing another screenshot.

Figure 3

Add Point/Area markers or adjust annotations (Figure 2). Live picking requires a fresh capture; existing targets remain. Resizing preserves marker positions and image proportions. Saved editing leaves playback running.

Edits autosave. Finish screenshot, Escape, closing either window, recompilation and Play transitions retain them. Cancel restores opening annotations while keeping other screenshot edits. Reopening resets Undo history; cancelled numbers stay unused. Submitted batches remain read-only.

Choose the exact target

Select Game object on a Game view capture and click a visible object. Candidates and their ancestors appear as read-only object fields. Click Select beside one to annotate that object, or focus its button and press Return. The object field pings on click and selects the object in Unity on double-click.

Figure 4

Dense overlaps show a warning if a camera reaches the 64-object candidate limit; isolate the intended object and recapture to see deeper candidates. Overlapping collider-free meshes and sprites can be picked; uGUI graphics remain pickable when their raycast target or gameplay interaction is disabled.

Select Editor control on an Editor window capture and click a control, then choose its element or ancestor. UI Toolkit targets retain type, name, classes, hierarchy position, bounds, binding path, and available source assets. Availability reports changes to source assets or the capture’s Play context. Bound Inspector fields also identify the inspected objects.

IMGUI candidates use the window name followed by area. Their bounds and window/Inspector context describe the captured region, rather than an exact retained control.

Picking uses the captured Game view’s camera and viewport mapping, including zoom and letterboxing. Changing the camera invalidates semantic picking; finish and recapture. uGUI uses rendered triangle geometry and masks; transparent texture pixels and custom shader clipping can still produce broader candidates. Camera stacking and custom rendering may need a point or area plus a descriptive note.

Send and retrieve a batch

Add a Message to agent if several markers need a shared instruction, such as “align #3 with #1.” Finish the active capture and complete every note, then click Send to agent. Missing notes or storage failures leave the draft available for correction and retry.

Figure 5

Click Copy request and paste it into your agent’s chat. You can copy an earlier request from Sent batches; hover its dated heading to see the full batch ID. Sending does not wake an idle chat. Through the existing Unity command tool, the agent can request:

{
  "project_path": "/absolute/path/to/project",
  "command": "get_annotation_batch",
  "args": { "batch_id": "<submitted-batch-id>" }
}

All three command responses carry schemaVersion: 1. list_annotation_batches returns pending summaries in batches. get_annotation_batch returns versioned metadata, all notes and target descriptors, and absolute paths to each original and preview PNG. After reading them, call acknowledge_annotation_batch with the same ID. Acknowledgment records retrieval; it does not claim the requested work is complete.

Drafts and submitted batches survive Editor restarts beneath UserSettings/UnityAnnotator. Submitted batches cannot be edited. Reads and repeated acknowledgments keep their files; open Sent batches and use Delete beside a batch to remove it explicitly. Waiting for agent changes to Read by agent after retrieval; that receipt does not mean the requested changes are complete. Runtime targets expire with their original Play session, while their screenshots and captured identity remain available as evidence.
